# Corpus completeness and later learning

The retained September 12 inventory contains 42 case records and 195 unique lesson rows with 362 source locations. It indexes 119 saved artifact directories, 89 complete four-file directories, 86 distinct complete sets, 2,346 patch paths and 1,974 patch hashes. These are inventory counts, not counts of accepted versions or verified chronological iterations.

The original audit report says it semantically synthesized all 195 lesson rows, the 42 case summaries, seven historical calibrators, two later owner confirmations and selected feedback. Preserve that attribution. No per-item read receipts establish a complete semantic review of every reference solution, review iteration or conversation. This later metadata audit inspected IDs, hashes, references and proof metadata; it did not reread those payloads.

Nine acceptance references exist, but all nine accepted artifact identities remain unverified. Task-specific links yield three distinct Lisette default-field solution hashes, three KiteSQL hashes, one Dora hash, four Rust Analyzer hashes and three Scylla hashes. Lisette's broad repository match also includes two unrelated tasks; exclude them from defaults iteration counts. The two accepted DataFusion tasks have no linked local solution revisions in the original snapshot; the physical-expression case is a different task.

The case records expose 455 named proof entries. Their labels can index check families, but labels and recorded exit codes do not establish execution, gate validity or complete coverage. Follow [execution-integrity.md](execution-integrity.md) and [partition-result-gate.md](partition-result-gate.md) for current evidence requirements. Historical private gates remain unknown where their contract or receipt is absent.

The 161 ZIP central directories and 2,126 members were inventoried without payload extraction. One KiteSQL submission bundle is malformed; a 103,725,762-byte Perry ZIP has metadata only because the old hash threshold was 64 MiB. The 745 excluded paths, remote-only material and unexported conversations remain outside the inventory. An absent reference is missing from this snapshot, not proof that it never existed.

## Post-evaluation learning

Separate a fresh reconstruction from later learning. Preserve the first artifact snapshot, validation-complete receipt, first archive exposure and first outcome before reading historical implementations. An early snapshot does not become a validated first-complete milestone retrospectively. Track metadata and generic exposure; withholding implementations does not certify blindness.

After case-specific authorization, hash each original prompt, reference patch and substantive review record before reading it. Deduplicate bytes, then establish iteration order from receipt/finding relationships rather than modification times. Map historical behavior to the original prompt and fresh assertions. Classify each difference as a confirmed gap, implementation alternative, additional scope, harness/environment defect, stale result or unproven finding. Do not silently edit the frozen benchmark or convert source inspection into an execution claim.

Retain a per-file read ledger and list unread unique variants, ZIP payloads, missing causal records and unverified acceptance bindings. Pending cases stay withheld until their own boundary and authorization. The bounded audit begins with Lisette, Scylla, Dora, Rust Analyzer and KiteSQL after their first archived evaluations; Calyx, Parquet, Ladybug and Aggregate payloads remain withheld at this audit point.

The metadata ledger and exact input hashes are retained in evidence/corpus-traceability-audit at the plugin source root. This evidence directory is a local audit attachment, not a claim that the full corpus is bundled in every plugin installation.

The later five-case payload sample is described in [post-evaluation learning](post-evaluation-learning.md). Its exact read ledger distinguishes one fully inspected solution, four partial solutions, nine structure-only variants and selected narrative coverage. It does not close the remaining corpus payload audit.
