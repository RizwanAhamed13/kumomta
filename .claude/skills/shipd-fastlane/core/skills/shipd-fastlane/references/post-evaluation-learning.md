# Learning from completed historical cases

Only inspect historical solutions after the fresh reconstruction's defined freeze and first archive evaluation, or when the task explicitly authorizes historical reconstruction. Record later exposure separately. A saved canonical path, live Accepted status or review narrative does not bind the accepted artifact bytes.

The September 13 bounded audit transferred 118 hashed files from five completed cases. It fully inspected one solution patch, portions of four others and 51 selected narratives; nine solution variants remain structure-only. All ZIP payloads and pending-case historical payloads remain unread. Exact path/hash/read extents live in evidence/corpus-traceability-audit/post-evaluation-learning/semantic-inspection-ledger.json in the private audit, with source links in the corpus completeness ledger. These are attributed historical observations, not freshly rerun historical results.

Use these relevant prevention steps alongside the current contract:

- Inventory syntax/input forms independently of the implementation. Dora's tuple/unit and guarded catchall repairs show that complete declared alignment can still omit a repository form. Include zero-element and nested/open-ended combinations when the prompt covers them.
- Exercise a whole state transition in one test. Scylla's preferred failure, fallback winner and following page need shared state; isolate latency with all other eligibility predicates satisfied. A generic filter callback cannot establish the latency updater behavior.
- Keep the oracle neutral to legal implementation choices. Opaque values may use private tuples or aliases; public constructibility is the observable constraint. Probe both fair alternatives and actual contract violations.
- Classify baseline outcomes before finalizing runner modes. Move unchanged baseline-valid safety checks to compatibility/base mode. Keep candidate-language compilation diagnostics distinct from harness compiler/setup failures. Never manufacture executed testcase failures from missing reports.
- Rebuild every affected local layer after patch application. Dora needed both the Rust compiler and Boots bootstrap; the first layer alone produced mixed-backend failures. Bind source and binary identities, offline dependencies, evaluator permissions and actual runner argument order.
- Treat similarly named revisions as separate contracts until proven identical. KiteSQL's core, scoped and v5 descriptions differ; Rust Analyzer's canonical patch lagged some review narratives. Preserve hashes and chronology instead of inferring latest bytes from names.

These steps are already represented by the [coverage workflow](test-coverage.md), [execution integrity](execution-integrity.md), [partition gate](partition-result-gate.md), [local quality gate](local-quality-gate.md) and [provenance rules](provenance.md). They do not add product requirements or make a local benchmark upload-ready. Historical practices superseded by these rules remain evidence of prior failures, not current instructions.
