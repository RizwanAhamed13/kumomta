## Workflow changes

1. Clear eligibility, denylist, occupancy, prior art and architectural depth before construction. Use accepted tasks to calibrate interacting semantics and discovery; file count alone is not hardness.
2. Inventory public inputs independently before writing tests. The contract checker then finds missing declared roles, orphan assertions, baseline-valid tests in new mode and ungrounded oracle types. It cannot prove the initial inventory complete.
3. Build the full natural reference and executable hardness evidence before reduced-test Scope. Preserve frozen problem, solution and representative Scope bytes during test expansion.
4. Reproduce findings on exact delivered bytes and repair confirmed adjacent defects together. Check compatibility consumers and feature-absent paths before fixing only the first failing review sentence.
5. Validate runner mode/option order, intended test discovery, real JUnit outcomes and exit status. Clean delivered-patch execution catches development-checkout, patch-collision and generated-file errors.
6. Fingerprint artifacts, repository commit, environment and selected commands. Reuse only matching complete passing receipts; list stale gates after every edit. The live panel controls paid-gate staleness.
7. Optimize runtime on shipd-builder through permitted build-time hydration, safe layer/cache reuse, affected-component rebuilds, combined commands and bounded jobs. Preserve all requirements and the full four-state matrix, with measured before/after durations.
8. Resume one concrete stage with a compact handoff and targeted lesson search. The default account-usage checkpoint stops expensive work at 40%, reserving headroom below the 50% ceiling.

## Local quality gate before upload — 2026-09-12

The installed workflow now requires author-side counterparts before each upload or re-upload: 12 checks for the reduced Scope boundary, 18 for the full package, and 20 for final review. The [local quality guide](/Users/rizwanahamed/plugins/shipd-fastlane/skills/shipd-fastlane/references/local-quality-gate.md) maps eligibility, originality, artifact contract, Scope, Verify Tests/Solution, test/task/fairness/solution/description quality, false positives, image runtime, flakiness, Quick Check, solvability, Holistic, Auto Review, rollout audit and final-state reconciliation.

A case-specific fresh panel capture must map every displayed check to its actual local behavior. The generic historical catalog does not establish current platform completeness. Unknown or unsupported checks block upload until their counterpart is supplied.

`quality_gate.py` creates PENDING templates, then audits real command outcomes, designated-builder identity and transfer evidence, raw rubric reviews, exact artifact/environment/selection fingerprints, hashed attachments, resolved findings and stage completeness. It rejects missing, failed, stale, malformed and unsupported receipts; it cannot attest the truth of arbitrary report prose or prevent uploads outside this workflow.
