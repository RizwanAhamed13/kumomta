Extend `CREATE INDEX` so an index, including a unique index, can use one of these key forms: `integer_column + integer_column`, `integer_column - integer_column`, `integer_column + non_negative_integer_literal`, or `CAST(cast_source AS BIGINT)`. Here, `integer_column` means a column declared `INTEGER`; `non_negative_integer_literal` means an `INTEGER` literal from 0 through 2147483647; and `cast_source` may be declared `INTEGER` or `BIGINT`. Reject constant-only keys. Evaluate the expression when the index is created over existing rows and whenever rows are inserted, updated, or deleted.

Persist the expression-index definition across database close and reopen. When a predicate constrains the complete stored expression, the applicable index must support equality and range scans, including a predicate comparison whose comparison constant is written on the left, and `EXPLAIN` must report an `IndexScan`. Match the expression using its full structure and referenced-column identities: a source column by itself or a different expression is not the stored index key. Selecting base columns through an expression-indexed predicate must not be reported as covering merely because the expression references them.

Support is required only for the listed key forms in single-key indexes. Schema-change handling is out of scope.
