# Support expressions in CREATE INDEX

Extend `CREATE INDEX` so an index, including a unique index, can use one of these key forms: `integer_column + integer_column`, `integer_column - integer_column`, `integer_column + non_negative_integer_literal`, or `CAST(cast_source AS BIGINT)`. Here, `integer_column` means a column declared `INTEGER`, while `cast_source` may be declared `INTEGER` or `BIGINT`. A `non_negative_integer_literal` includes values inferred as `BIGINT`, such as `2147483648`, and follows normal numeric coercion with the `INTEGER` column. Reject constant-only keys. Evaluate the expression when the index is created over existing rows and whenever rows are inserted, updated, or deleted.

Persist the expression-index definition across database close and reopen. When a predicate constrains the complete stored expression, the applicable index must support equality and range scans, including a predicate comparison whose comparison constant is written on the left, and `EXPLAIN` must report an `IndexScan`. A stored `integer_column + non_negative_integer_literal` expression remains the key when matching predicates on that same expression. Match expressions using their full structure and referenced-column identities: an index on `a + b` is not an index on `a` alone, and a different expression is not the stored key. Selecting base columns through an expression-indexed predicate must not be reported as covering merely because the expression references them.

Support is required only for the listed key forms in single-key indexes. Schema-change handling is out of scope.
